# Migrate an existing brain without exposing private work

Migration is not a fresh interview. Preserve the existing installation and reuse its facts. The 0.2 kit did not have a shared-only wiki, so do not attach a company remote before reviewing its contents.

For 0.4.x to 0.5.0, the setup schema, sync baseline, and content locations are unchanged. Merge the updated AGENTS.md, workflows/references, core skill sources, and version metadata from an inspected starter while preserving client customizations. Keep personal/, wiki/, corrections/, setup.json, sync-state.json, skills.json, and the installation's existing seed-shared.json; a new starter seed must not redefine old user content as untouched template content. Reinstall updated core skills through the global skills flow and verify the app loads them. Do not run setup again, reset repositories, or recopy template data. Apply corrected routing to current requests; review ambiguous old preferences with the user rather than bulk-moving them into company knowledge. Clearly misfiled shared rules can be moved within an authorized correction, with normal company review before publication.

For 0.3.x to 0.4.0, personal content locations and the sync baseline schema are unchanged. From a separately inspected current starter, update the runtime scripts (including repository-files.mjs), workflows/references, core skill sources, AGENTS.md/CLAUDE.md, and kit.json, preserving any user customizations. Do not copy maintainer tests, release files, package.json, or folder-placeholder READMEs into a client installation. Preserve personal/, wiki/, corrections/, setup.json, sync-state.json, and skills.json. Keep the client's README until configure compares it against known template fingerprints; it replaces an unchanged starter README and preserves custom text. Do not replace the README wholesale during the update.

Run configure with existing choices after the runtime update. It uses the starter cleanup fingerprints from kit.json to remove recognized unchanged development material, then discards those fingerprints from the installed metadata. It reports customized files it retained; inspect those separately rather than deleting them blindly. Reinstall updated core skills through the global skills flow, then resume sync. Do not relocate user content or repeat answered questions.

Version 0.4.0 permits separate company root README.md and AGENTS.md. Update all syncing teammates before approving the first batch adding them: older helpers reject these files. Existing company history containing only wiki/ and corrections/ needs no rewrite. The helper generates missing root documents for review and never imports company root instructions over personal ones. Do not force an update or full-tree push to work around an older helper.

2. Verify which versions are already recoverable from Git. Preserve uncommitted user material before substantial replacement, using a private recovery copy only when necessary. Do not duplicate the starter into an archive or remove an unknown computed path.
3. Move private context and memory into personal/ with links from preferences.md. Move projects and private research into personal/projects/ and personal/research/. Preserve source dates, approvals, and the project registry.
4. Review each old company profile/rule/wiki source. Only confirmed company-shareable material moves into wiki/. Keep unrelated clients and private sources under personal/. Never use a broad directory copy as sharing approval.
5. Replace the operating instructions/support files selectively from a separately inspected Git checkout of the new kit. Do not merge starter history into personal data blindly. Remove the temporary starter remote after inspection.
6. Review and remove exact obsolete hook/task registrations before removing the old entry points or enabling a new routine. The new starter does not ship legacy sync scripts. Do not repurpose old entry points as active upload commands.
7. Remove an origin remote only after identifying it as the LeanLabs0 starter. An origin that points to an existing personal backup may be renamed personal after verifying the destination. Unknown remotes require investigation.
8. Configure new personal/company destinations and protections, register the brain, and install selected global skills. Do not carry an old shared baseline into a different company.
9. Run backup, company preparation, and the first explicit review. Verify recovery and fresh-conversation recall.
