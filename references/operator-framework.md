# Improve the work before automating it

Use this optional framework when deciding how to improve a repeated task. It is a discussion aid, not a prerequisite for ordinary work or a promised productivity outcome.

## Mindset: find the opportunity

Notice repeated copying, explaining, searching, or correcting. Ask which part AI could help with. Break a large job into smaller tasks and start where the input and desired result are clearest.

A tool that failed before may improve, but check current capability on a real example. Do not assume a fixed productivity gain or timeline.

## Method: choose the smallest useful change

First ask whether a step can be removed. Then simplify what remains. A checklist or saved prompt may solve the problem without any integration.

Identify the input, the useful output, and the decisions requiring human judgment. Choose the least autonomy that serves the user's need. A draft for review is often enough.

Agree on an observable improvement: less time searching, fewer corrections, a usable brief, or fewer missed follow-ups. A financial metric is helpful where relevant, not mandatory.

## Machine: build and verify

Use predictable transformations for predictable work. Add AI where interpretation helps. Test each important part with representative inputs, then verify the complete result.

Start by running the workflow when asked. Schedule it only after its behavior is understood and the user wants a schedule. Define permissions, expected cost, failure reporting, ownership, and how to stop it.

Prefer supported sign-in and scoped connections. Do not treat an authenticated tool as authorization for every action it can perform.

Retire workflows that cost more to maintain than they save. Keep the reusable learning and remove unnecessary machinery.
